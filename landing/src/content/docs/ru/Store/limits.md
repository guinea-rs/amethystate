Store отклоняет значения, которые его кодек не сможет прочитать обратно.
Можно задать более строгие ограничения, но нельзя отключить эти проверки.

## Насколько глубоко может вкладываться значение

Глубина учитывает вложенные структуры, последовательности и карты внутри
значения. У рекурсивных типов, например дерева или меню, она зависит от данных.

Сериализатор может записать более глубокие данные, чем способен прочитать
десериализатор. Без проверки запись прошла бы успешно, а следующее открытие
завершилось бы ошибкой. В текстовом движке одно слишком глубокое значение
может помешать разбору всего документа.

Поэтому store считает уровни во время сериализации и останавливается до
предела чтения. Подсчёт в проходе кодека также позволяет не строить сначала
глубокое промежуточное значение, способное переполнить стек.

<!-- shown: how deep the engine you are running reads -->
```rust
let engine = default_backend();
println!("{}: {} levels", engine.extension(), engine.depth_ceiling());
```
<!-- /shown -->

Действующие пределы проверяются в `tests/probe_*.rs`:

| движок | уровней |
| --- | --- |
| redb | 512 |
| JSON | 127 |
| SQLite | 127 |
| TOML | 80 |
| RON | 64 |

У кодека redb нет подходящего встроенного ограничения рекурсии. Предел
в 512 уровней задан библиотекой, чтобы остановиться до исчерпания стека.
Это не гарантия конкретного размера стека на любой платформе.

### Путь тратит тот же бюджет

Глубина пути тоже учитывается. В текстовом документе `ui.panels.left`
добавляет три уровня ещё до вложенности самого значения. Общая проверка
вычитает глубину пути и для SQLite, хотя его ключ не добавляет вложенность
JSON: это консервативное ограничение.

Ошибка глубины сообщает общий бюджет, число уровней пути и остаток
для значения.

## Два предела, которые можно задать

Более строгие ограничения задаются через `limits`. Поднять безопасный
предел движка ни одна настройка не может:

<!-- shown: capping how deep a path may go -->
```rust
let store = StoreBuilder::new(settings)
    .limits(|l| l.key_depth(4))
    .build()?;

let deep = StorePath::from_segments(["a", "b", "c", "d", "e"]);

if let Err(refused) = store.set(&deep, &1u32) {
    println!("{refused:?}");
}
```
<!-- /shown -->

`key_depth` отклоняет слишком длинный путь до кодирования значения.
Это полезно для путей, собираемых во время работы: случайную рекурсивную
вложенность лучше обнаружить при записи, а не при следующем открытии файла.

<!-- shown: promising the contents stay readable on another engine -->
```rust
let store = StoreBuilder::new(settings)
    .limits(|l| l.portable_across([default_backend()]))
    .build()?;
```
<!-- /shown -->

`portable_across` перечисляет другие движки, на которых значения тоже должны
читаться. Итоговый предел глубины — минимальный среди текущего и перечисленных
движков. Например, redb с переносимостью в RON допускает 64 уровня вместо 512.

Проверки переносимости также учитывают:

| свойство | ограничение |
| --- | --- |
| `NaN` и бесконечности | JSON и SQLite не сохраняют их как числовые значения. |
| enum-варианты | Дерево значений RON, используемое движком, их не сохраняет. Типы вроде `IpAddr`, сериализующиеся строкой в человекочитаемом формате, проверяются в этом представлении. |
| `Some(None)` | Все движки, кроме RON, теряют различие вложенных `Option`. |
| `u128` и `i128` | TOML и RON не поддерживают 128-битный тип, даже если само число маленькое. |
| целые вне `i64` | Выходят за диапазон целых TOML. |
| целые вне обоих диапазонов `i64` и `u64` | Представление значений JSON не сохраняет их как целые. |

Текущий движок участвует в проверке всегда. Поэтому store на JSON отклоняет
NaN даже без явной настройки переносимости.

Перечисляйте только нужные движки. Неявное «все движки» меняло бы смысл
при каждом добавлении нового движка.

## Чего это не покрывает

Проверки охватывают глубину и свойства из таблицы, но не все различия форматов.
Другие проверенные ограничения — в
[Выборе движка](/amethystate/ru/choosing/absent-or-null/).
