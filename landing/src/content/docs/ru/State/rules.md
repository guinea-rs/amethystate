Позиция окна −32000, кегль ноль и имя темы, которую никто не ставил,
декодируются прекрасно. [Когда значение не читается](/amethystate/ru/state/unreadable-values/)
— про байты, которые не читаются, а `rule` — то место, где приложение говорит,
чего у него не будет среди тех, что читаются.

Правило объявляют один раз, на поле, и оно стоит на каждом пути, которым
значение проходит через это поле, в обе стороны:

- **внутрь** — прочитано из store, когда структуру строят или загружают;
  принесено правкой файла; записано в обход поля — по пути через `Store::set`
  или из фронтенда Tauri;
- **наружу** — записано самим процессом через `set`, `update` или `modify` или
  сохранено `save` у загруженной структуры.

Объявленного значения по умолчанию среди них нет. Это собственное значение
объявления, и его берут как написано: когда в store ничего нет, после
`UseDefault` и как первое значение `volatile`-поля. Если правило такое значение
не пропустило бы, менять надо значение по умолчанию.

Что бы оно ни решило, это доходит до обеих сторон. Поправленное правилом — то,
что держит поле, и то, что держит store: поправку на входе записывают обратно в
store, а поправку при `save` оставляют в структуре у вас в руках. Отклонённое
на выходе не записывается никуда. Так что никому не приходится подрезать
значение перед `set`, чтобы оно не вышло за рамки, и ни один экран не покажет
того, чего нет в файле.

## Как его написать

Правило — голая `fn`, берёт значение и контекст, а отвечает причиной, а не
`bool`. Причину покажет `try_get`, её же несут отказ при открытии и отклонённая
запись, — значит и пишут её для того, кто потом будет чинить значение.

Значение правило берёт по `&mut`: если оно знает, каким значение должно было
быть, оно вправе его поправить и ответить `Ok`. О том, что была поправка,
никто не сообщает: прошло — значит прошло, третьего состояния между «принято» и
«отказано» нет.

<!-- shown: a rule on a field, and the world it is judged against -->
```rust
fn a_size_that_renders(size: &mut u8, _cx: &RuleContext) -> Result<(), Invalid> {
    if *size >= 6 {
        Ok(())
    } else {
        Err(Invalid::new("a font size below 6 renders nothing"))
    }
}

fn a_theme_that_is_installed(theme: &mut String, cx: &RuleContext) -> Result<(), Invalid> {
    let installed = cx.require::<InstalledThemes>()?;

    if installed.0.contains(&theme.as_str()) {
        Ok(())
    } else {
        Err(Invalid::new(format!(
            "no theme called {theme} is installed"
        )))
    }
}

#[amethystate(prefix = "checked_lenient", on_unreadable = UseDefault)]
pub struct LenientUi {
    #[amestate(default = 14u8, rule = a_size_that_renders)]
    pub font_size: u8,

    #[amestate(default = "dark".to_string(), rule = a_theme_that_is_installed)]
    pub theme: String,
}
```
<!-- /shown -->

Контекст нужен потому, что правило — голая `fn`: оно ничего не захватывает.
Мир, по которому она судит значение, — какие есть мониторы, какие темы
установлены, — передают store при открытии.

```rust
let store = StoreBuilder::new(settings)
    .context(InstalledThemes(installed))
    .build()?;
```

По одному значению на тип, спрашивают через `cx.get::<T>()` или
`cx.require::<T>()`. Если не передали ничего, `require` отклоняет значение:
правило, которое не дотянулось до своего мира, не вправе назвать значение
хорошим.

## Запись, которую правило отклонило

Запись, которую правило отклонило, не ложится: поле держит прежнее, ничего не
записано, а сама запись отвечает `WriteValue::Refused` с путём и причиной.

<!-- shown: a write the rule turns down -->
```rust
match ui.font_size().set(3) {
    Ok(()) => {}
    Err(WriteValue::Refused { at, said }) => eprintln!("{at} will not take it: {said}"),
    Err(other) => return Err(other.into()),
}
```
<!-- /shown -->

Запись, которую правило поправило, ложится такой, какой её оставило правило, —
и в поле, и в store.

## Сохранённое значение, которое правило отклонило

Отклонённое значение, прочитанное из store, — та же ситуация, что и у
`on_unreadable`, и разбирают её тем же способом. `Refuse` валит построение и
называет путь и причину. `UseDefault` берёт значение из `default`, оставляет
сохранённое на диске и отвечает на `try_get` через `Err`, пока не пройдёт
какое-нибудь изменение.

Провалившееся построение отдаёт `OpenStruct` — шесть способов упасть, которые у
конструктора есть, и никаких других, — так что один отказ отличают от другого по
варианту, а не по тексту:

<!-- shown: telling one refused open from another -->
```rust
match StrictUi::new_with(&store) {
    Ok(_) => {}
    Err(OpenStruct::Refused { at, said }) => eprintln!("{at} will not do: {said}"),
    Err(OpenStruct::WillNotRead { at, why }) => eprintln!("{at} is unreadable: {why}"),
    Err(OpenStruct::Taken(taken)) => {
        eprintln!("{} already holds {}", taken.held_by, taken.at)
    }
    Err(other) => return Err(other.into()),
}
```
<!-- /shown -->

При `UseDefault` ничего не падает, и то же место с той же причиной приходят
через поле — как `Disagreement`: это не провал самого вопроса, а то, о чём поле
и store не договорились.

<!-- shown: asking a field what the store disagrees with -->
```rust
let held = match ui.font_size().try_get() {
    Ok(size) => size,
    Err(no) => {
        match no.reason {
            Reason::Refused(said) => eprintln!("running on the default: {said}"),
            Reason::WillNotRead(said) => eprintln!("{} will not decode: {said}", no.at),
            Reason::Occupied(said) => eprintln!("{} was already taken: {said}", no.at),
            _ => eprintln!("{} is not what the store has", no.at),
        }

        ui.font_size().get()
    }
};
```
<!-- /shown -->

`Reason::Refused` появляется только там, где значение завернуло объявленное
правило. Байты, которые не декодировались, приходят как `WillNotRead` — с
фразой самого кодека, — а поле, так и не записавшее свой `default`, потому что
store уже что-то там держал, как `Occupied`. Поле закрытого store отвечает
`Reason::Closed` — это четвёртый, отдельный случай: значение в нём последнее,
что оно слышало. А `Reason::NotWrittenBack` значит, что правило поправило
сохранённое значение, а store поправку не взял: поле держит поправленное, store —
то, что ему дали.

`Reason` помечен `#[non_exhaustive]` — это список того, в чём поле и store
бывают не согласны, и он растёт, — поэтому `match` по нему держит ветку `_`.
Наборы её не держат, и [Ошибки](/amethystate/ru/concepts/errors/) объясняют
почему.

## Где правило выполняется, а где нет

| значение | правило поля |
| --- | --- |
| прочитано, пока строится структура | выполняется; поправка записывается обратно |
| записано через поле: `set`, `update`, `modify` | выполняется; после отказа поле и store остаются как были |
| записано в обход поля: `Store::set` по пути, фронтенд Tauri | выполняется, когда значение приходит; отказ оставляет последнее хорошее значение и никого не будит, поправка записывается обратно |
| правка извне процесса | выполняется, когда значение приходит, так же |
| `load_with` | выполняется; поправка записывается обратно |
| `save` у загруженной структуры | выполняется на всех полях до первой записи; отказ валит сохранение |
| шаг миграции | не выполняется |

Две строки отсюда стоит прочитать дважды.

**Запись в обход поля судят уже после того, как store её принял.** Поле
узнаёт о ней позже store, поэтому отклонённое правилом остаётся в файле, поле
держит последнее хорошее значение, а сама запись отвечает, что подписчик не
смог её принять. Поправленное правилом записывается поверх пришедшего, и в
файле оказывается то же, что держит поле.

**При `mode = "persistent"` нет `Field`, значит нет и `try_get`.** Отклонённое
значение при `UseDefault` берёт значение из `default` и пишет об этом в лог —
больше об этом нигде не скажут. `Refuse`, который стоит по умолчанию, вместо
этого валит загрузку; за ним и тянитесь, когда загруженной структуре надо
доверять.

`save` берёт структуру по `&mut` и проводит каждое поле через его правило,
прежде чем что-нибудь записать. Что правило поправило, оно поправило и в
структуре в руках, так что после сохранения в ней то же, что в файле. Отказ
валит сохранение с `WriteValue::Refused`, а раз все правила прошли до первой
записи, из структуры не записывается ничего.

## Куда правило ставят, а куда нет

Правило берёт и `volatile`-поле. Из store в него ничего не приходит, зато
каждая запись идёт через правило, и оно держит в рамках значение, которое
процесс хранит в памяти и никуда не кладёт.

Два поля правила не примут вовсе, и макрос скажет об этом на компиляции:

- **`nested`-поле.** Правило поля судит одно значение по одному пути.
  Вложенная структура — не значение, а поддерево путей, и звать правило не с
  чем. Правила вешают на поля самой вложенной структуры.
- **Карта.** Правило объявляют один раз и про одно значение, а записи карты —
  данные: они приходят и уходят на ходу, и объявленного пути, на который
  повесить правило, у них нет. Что карта делает с записью, которую не может
  прочитать, решает `unreadable_entries` — это на странице
  [Поля](/amethystate/ru/state/fields/), а не здесь.

Не примет правила и структура. Структура — место, где лежат поля, а не
значение само по себе, поэтому инвариант между двумя полями — наименьшая
ширина не больше наибольшей — проверяют там, где структуру открывают:
[Как открыть структуру по-своему](/amethystate/ru/state/opening-structs/).

Для того, чего объявлением не скажешь, есть
[перехватчик](/amethystate/ru/concepts/subscriptions/#перехватчики): правило, которое
появляется и исчезает, пока программа работает, — его ставят на хендл и
снимают.
