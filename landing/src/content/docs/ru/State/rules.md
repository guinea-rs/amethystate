Значение может успешно десериализоваться, но не подходить приложению:
например, нулевой размер шрифта или имя недоступной темы. Используйте `rule`,
чтобы нормализовать такие значения. Данные, которые вообще не удаётся
десериализовать, обрабатывают [политики чтения](/amethystate/ru/state/unreadable-values/).

Правило поля обрабатывает значения при чтении из хранилища и записи из приложения:

- **внутрь** — прочитано из store, когда структуру строят или загружают;
  принесено правкой файла; записано в обход поля — по пути через `Store::set`;
- **наружу** — записано самим процессом через `set`, `update` или `modify` или
  сохранено `save` у загруженной структуры.

**Значения по умолчанию не проходят через правило.** Это касается отсутствующего
ключа, `UseDefault` и начального значения volatile-поля. Задайте default,
который уже удовлетворяет правилу.

Правило меняет значение через `&mut`, а не отклоняет его: например, ограничивает
размер или заменяет недоступную тему. Поле использует исправленное значение,
а исправление при чтении записывается обратно в store. При сохранении
загруженной структуры исправленное значение остаётся и в ней. Вызывающему коду
не нужно повторять одну и ту же нормализацию перед каждой записью.

## Как его написать

Правило — голая `fn`: берёт значение и контекст и ничего не возвращает.

<!-- shown: a rule on a field, and the world it is judged against -->
```rust
fn a_size_that_renders(size: &mut u8, _cx: &RuleContext) {
    *size = (*size).clamp(6, 72);
}

fn a_theme_that_is_installed(theme: &mut String, cx: &RuleContext) {
    let installed = cx.require::<InstalledThemes>();

    if !installed.0.contains(&theme.as_str()) {
        *theme = "dark".to_string();
    }
}

#[amethystate(prefix = "ruled_ui")]
pub struct Ui {
    #[amestate(default = 14u8, rule = a_size_that_renders)]
    pub font_size: u8,

    #[amestate(default = "dark".to_string(), rule = a_theme_that_is_installed)]
    pub theme: String,
}
```
<!-- /shown -->

Правило — указатель на функцию, а не замыкание с захватом. Нужные ему данные,
например доступные мониторы или установленные темы, передавайте через контекст store:

```rust
let store = StoreBuilder::new(settings)
    .context(InstalledThemes(installed))
    .build()?;
```

Контекст хранит одно значение на тип. `cx.get::<T>()` возвращает `None`, если
типа нет. `cx.require::<T>()` паникует с отсутствующим и доступными типами,
чтобы пропущенная обязательная зависимость обнаружилась при настройке.

## Запись, которую правило поправило

Поле и store получают нормализованное значение:

<!-- shown: a write the rule puts right -->
```rust
ui.font_size().set(200);

assert_eq!(ui.font_size().get(), 72);
assert_eq!(store.get::<u8>(["ruled_ui", "font_size"])?, Some(72));
```
<!-- /shown -->

## Где правило выполняется, а где нет

| операция | поведение |
| --- | --- |
| Открытие или загрузка поля | Нормализовать прочитанное и записать исправления обратно. |
| `set`, `update`, `modify` через поле | Нормализовать до записи. |
| `Store::set` по пути | Нормализовать при получении изменения живым полем, затем записать исправления. |
| Внешняя правка файла | Обработать как входящее сохранённое значение. |
| Сохранение persistent-only структуры | Выполнить правила всех полей до начала записей. |
| Шаг миграции | Не выполнять правила полей. |

Прямая запись по пути сначала принимается store, а затем обрабатывается живым
полем. Оно нормализует значение и при необходимости записывает исправление.
Это не общая проверка store, которая блокирует исходную запись заранее.

Если исправление записать не удалось, поле хранит нормализованное значение,
а `try_get` сообщает `Reason::NotWrittenBack`.

Persistent-only `save` принимает `&mut self`, поэтому нормализованные значения
остаются и в загруженной структуре, и записываются в хранилище.

## Куда правило ставят, а куда нет

У volatile-поля может быть правило локальных записей, хотя данные не сохраняются.
Макрос отклоняет `rule` на:

- **Вложенном поле:** оно описывает несколько путей, не одно листовое значение.
  Задайте правила отдельным полям компонента.
- **Карте:** у динамических записей нет отдельных объявлений полей.
  `unreadable_entries` управляет ошибками чтения, не нормализацией.

Общего правила структуры нет. Проверки нескольких полей при создании размещайте
в [Open](/amethystate/ru/state/opening-structs/), а при последующих изменениях
поддерживайте инвариант кодом приложения.
