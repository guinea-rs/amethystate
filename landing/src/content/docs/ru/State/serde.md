Атрибуты объявления состояния и атрибуты сохраняемого значения решают разные задачи.

Структура с `#[amethystate]`, в том числе компонент `nested`, описывает пути
хранения. Её поля сохраняются отдельно; само объявление не сериализуется
единым значением. Пути и поведение полей настраиваются через `#[amestate(..)]`.

Serde-атрибут на объявлении или его поле не настраивает amethystate.
Без соответствующего derive serde компилятор отклоняет его:

```
error: cannot find attribute `serde` in this scope
  = note: `serde` is an attribute that can be used by the derive macros
          `Deserialize` and `Serialize`, you might be missing a `derive` attribute
```

Неизвестные макросу атрибуты переносятся на сгенерированные поля.
Макрос не превращает serde-атрибуты в настройки хранения.

**Листовое значение** устроено иначе: оно сериализуется целиком по одному
пути. Его тип может выводить трейты serde и использовать их атрибуты как обычно.

## Чем это сказать здесь

Для объявлений состояния используйте следующие атрибуты:

| у serde | здесь |
| --- | --- |
| `rename = ".."` | `#[amestate(path = "..")]`; точки разделяют сегменты пути, а не входят в одно имя |
| `rename_all = ".."` | `rename_all` в `#[amethystate(..)]` |
| `default` на поле | `#[amestate(default = ..)]` с выражением вместо пути к функции |
| `flatten` | `#[amestate(flatten)]` на `nested`-поле; меняет пути хранения |
| `with`, `serialize_with`, `deserialize_with` | соответствующие атрибуты `#[amestate(..)]` с теми же функциями |

`tag`, `untagged`, `transparent`, `deny_unknown_fields` и похожие атрибуты
настраивают одно сериализуемое значение, а не набор отдельных путей.
Для нечитаемых полей есть `on_unreadable`, для данных только в памяти —
`volatile`. Ранее сохранённые данные переносит шаг миграции.
`#[rename(old => new)]` фиксирует переименование, но не заменяет тело
функции преобразования.

Полный справочник — [Поля](/amethystate/ru/state/fields/).

## Внутри листа

Кодек сериализует листовое значение целиком, поэтому serde-атрибуты
действуют как обычно:

<!-- shown: a leaf, where serde answers to nobody here -->
```rust
#[derive(Serialize, Deserialize, Default, Clone, Debug, PartialEq)]
#[serde(rename_all = "kebab-case", deny_unknown_fields)]
pub struct Endpoint {
    pub host_name: String,

    #[serde(default)]
    pub port: u16,
}

#[amethystate(prefix = "svc")]
pub struct Service {
    #[amestate(default = Endpoint { host_name: "localhost".to_string(), port: 443 })]
    pub upstream: Endpoint,
}
```
<!-- /shown -->

Здесь `Endpoint` сохраняется по пути `svc.upstream`; serde задаёт имена
членов и отклоняет неизвестные поля при десериализации.

За изменениями внутри листа нужно следить отдельно:

- **Внутреннее переименование не определяется как дрейф схемы.** Путь хранения
  остаётся прежним. Обеспечьте чтение старых данных новым типом или преобразуйте
  их в миграции.
- **`deny_unknown_fields` ограничивает совместимость вперёд.** Старый тип
  отклоняет поля, добавленные новой версией.
- **У новых полей должно быть поведение при отсутствии.** В форматах с именованными
  членами `#[serde(default)]` позволяет новому типу прочитать данные, записанные
  до появления поля. Без default отсутствие обязательного поля ломает чтение
  всего значения.
- **Позиционные форматы требуют осторожности.** Вставка элемента кортежа может
  сдвинуть последующие значения. Именованные поля Rust сами по себе не гарантируют
  именованное хранение — проверьте выбранный кодек.

## Что формат вообще донесёт — другой список

Поддержка serde не означает поддержку каждым движком. Кодек может отклонить
перечисление, неконечное число или целое вне диапазона, даже если тип реализует
трейты serde. Проверенные ограничения форматов приведены в
[Выборе движка](/amethystate/ru/choosing/).
