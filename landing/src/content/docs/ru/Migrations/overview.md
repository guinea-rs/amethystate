## Для чего нужны миграции

Допустим, старая версия сохраняла `host`, а новая ожидает `address`.
Переименование поля Rust само по себе не переносит сохранённое значение.
Миграция читает старые данные и записывает их в виде, который ожидает новая версия.

Вы задаёте версии структур и пишете функции преобразования.
`StoreBuilder::migrate` выполняет нужные шаги при открытии store,
прежде чем вернуть его приложению.

## Что мигрирует, а что нет

Мигратор работает исключительно с сохраняемыми данными.

| Вид поля | Мигрирует? |
|------------|-----------|
| Обычные поля | ✓ |
| Структуры `nested` | ✓ |
| Поля `volatile` | ✗ — только в памяти, сохранённых данных нет |

## Как работает версионирование

У каждой структуры `#[amethystate]` есть атрибут `version`, по умолчанию `0`:

```rust
#[amethystate(prefix = "app", version = 2)]
pub struct AppConfig { ... }
```

Версии отслеживаются по **линиям**: префиксу вместе с `id` структуры,
если он задан. Мигратор сравнивает сохранённую версию с версией в коде
и выполняет зарегистрированную цепочку шагов между ними.

Если в цепочке есть разрыв, store не откроется. Данные с более новой схемой
тоже не откроются: старое приложение не должно трактовать их как старые данные.

## Автоматический сбор

`migrate` собирает все шаги, объявленные через `#[migrate]`, и отдаёт отчёт о том, что сделал:

```rust
let (store, report) = StoreBuilder::new("./app.redb").migrate()?;
```

Шаги, объявленные макросом, не нужно регистрировать отдельно. Но для их
выполнения нужно вызвать `migrate`: `build` не запускает шаги миграции,
даже если в бинарнике есть функции с `#[migrate]`.

Если шагу нужен низкоуровневый доступ или данные другой структуры,
см. [Ручные миграции](/amethystate/ru/migrations/manual/).

## Что происходит при чистой установке

Новый пустой store начинает с текущей версии схемы, без выполнения старых
шагов миграции. При открытии структуры поля получают объявленные значения
по умолчанию: старых пользовательских данных для преобразования ещё нет.

## Когда структура изменилась, а версия — нет

Изменение схемы без увеличения `version` не запускает миграцию. Библиотека
сообщает о расхождении как о дрейфе и продолжает открытие store. Отчёт
повторяется при следующих открытиях, пока расхождение не исправлено.
Подробнее — [Дрейф схемы](/amethystate/ru/migrations/drift/).
