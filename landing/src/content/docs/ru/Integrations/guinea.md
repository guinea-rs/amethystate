---
title: guinea
---

`amethystate-guinea` связывает таймер [guinea](https://crates.io/crates/guinea)
с реактивной настройкой. При её изменении ожидание перезапускается с новым
интервалом — независимо от того, изменили значение из интерфейса, другого
потока или правкой файла.

## Установка

```toml
[dependencies]
amethystate-guinea = "0.29"
```

Версия адаптера совпадает с amethystate; нужен Rust 1.95.
Зависимость от guinea задана как `>=0.32`, без верхней границы. Новый minor-релиз
guinea сам по себе не требует перевыпуска адаптера; несовместимое изменение API
таймера всё ещё может потребовать обновления. Эта версия проверена с guinea 0.32, 0.33 и 0.34.
Для guinea 0.31 нужен адаптер 0.28; для guinea 0.30 — 0.27.
Дефолтные фичи guinea отключены: бэкенд интерфейса
и runtime выбирает приложение.

## Период по полю

```rust
use amethystate_guinea::IntoChanging;
use guinea::sources::Period;
use std::time::Duration;

cx.every(
    Period::follows(settings.ping_interval_ms().changing(), Duration::from_millis),
    || Ping,
    agent.clone(),
);
```

`changing()` адаптирует поле для `Period::follows`. Таймер читает значение
перед каждым ожиданием и подписывается на изменения. Правка прерывает текущее
ожидание; следующий тик наступит через новый интервал. Таймер принадлежит
скоупу: выход из скоупа завершает таймер и его подписку. Удаление возвращённого
хэндла `Source` таймер не останавливает.

Поле может изменяться в любом потоке; guinea перезапускает ожидание на потоке UI.

## Период по записи карты

`ReactiveCell` тоже поддерживает `changing()`, поэтому таймер может следить
за одной записью карты:

```rust
let ping = intervals.entry_cell("ping".to_string());

cx.every(Period::follows(ping.changing(), Duration::from_millis), || Ping, agent.clone());
```

Если записи нет, интервал отсутствует и таймер приостанавливается.
Добавление ключа запускает таймер; удаление записи или её исходной карты
снова его приостанавливает.
